# ATHENA Interactive MVP

这是 ATHENA / HAST-DT 的可运行交互原型，用来验证：

- 身体状态输入是否容易理解；
- 退役运动员的专项、退役阶段、身体感受、生活目标和训练节奏是否能进入个体化决策；
- 红旗症状是否会阻止不安全的测试和干预；
- 60 分钟连续坐姿触发后，用户能否完成一次低负担决策；
- 接受、延后、版本和安全门控是否都能写入研究日志。

## 运行动态版本

当前版本已经不是单纯的静态网页，而是一个带后端 API 的动态 MVP。Node.js 服务负责提供页面、创建会话、保存运动员画像、今日状态和事件记录；会话数据暂时写入本地 `data/athena-sessions.json`，后续部署腾讯云时可以替换为 MySQL 或云数据库。

需要 Node.js 18 或更高版本：

```bash
npm start
```

打开 `http://127.0.0.1:8765/`。

动态接口包括：

- `GET /api/health`：服务健康检查；
- `GET /api/session`：读取当前浏览器会话；
- `PUT /api/session`：保存画像、今日状态和事件记录；
- `POST /api/events`：写入单条研究事件。

## 演示路径

1. 先打开“运动员档案”，回答过去主要练什么、离开系统训练多久、今天希望解决什么；身体关注区域可以选择“我不确定，先跳过”；
2. 也可以直接在首页走“今天的互动引导”：今天感觉 → 今天目标 → 个性化动作 → 进入任务；
3. 在“今日状态”选择“还可以 / 有点累 / 有点不舒服”，不需要先填写精确数字；
4. 点击“模拟再坐 20 分钟”，累计到 60 分钟；
5. 在“干预任务”观察“赛后恢复式”任务；如在画像中选择“膝盖/腿部”，可以看到身体关注信息对“站起来，再坐下”的安全门控；
6. 在“身体检查”勾选“胸部不适”等红旗症状，观察安全层如何暂停主动干预；
7. 在“研究记录”导出本次演示 JSON。

## 退役运动员专属能力

ATHENA 的特色不是换一套视觉主题，而是把“运动员身份转型”变成可审计的软件状态：

- **专项与退役阶段画像**：区分球类、田径、游泳、水上、耐力/户外、力量/举重等训练背景，并记录退役不到 1 年、1–3 年、3–5 年或 5 年以上的阶段；
- **更宽的专项选择**：覆盖田径、游泳、水上、耐力/户外、力量/举重、体操/技巧、武术/格斗、冰雪和轮滑/极限等类别，并允许补充具体项目；
- **身体关注信息写入任务排序**：用户只需报告“哪里需要少一点负担”，也可以跳过；系统可以据此收窄候选任务，但不诊断、不自动开具运动处方；
- **训练—生活节奏差距**：比较退役前训练量与当前主动活动，帮助识别“从高训练量突然进入久坐工作日”的转型断层，而不是只看步数；
- **目标驱动的任务顺序**：想减少久坐时优先给出走动，想安全活动时优先给出原地活动，想找回节奏时优先给出两分钟恢复；画像会改变下一步，而不只是被保存；
- **三步互动引导**：不用先填完整档案，用户可以从“今天感觉如何”开始，逐步选目标并直接进入个性化任务；
- **首屏价值钩子**：第一屏直接说明“不是重新训练、不是只看步数、不是一直催你”，让用户先理解 ATHENA 对退役运动员的独特价值，再进入互动；
- **可调的运动员语言**：用户可以选择提醒保留多少“训练感”；系统会在“下一组恢复”和“换个姿势、走两步”等表达之间切换，但语言层不能改变固定任务的强度或时长；
- **身份转型视角**：把恢复、工作日结构和新的生活角色纳入画像，为后续加入职业、社交、心理和睡眠模块预留接口。

当前动态 MVP 使用浏览器会话 Cookie 区分用户，并在服务器端保存演示数据。正式研究需进一步加入登录、知情同意、数据最小化、访问控制、审计、人工复核和伦理审批流程；“身体关注信息”不能替代临床评估。

相关研究依据可从以下入口继续扩展：

- [After Career Consultation for retired footballers](https://pubmed.ncbi.nlm.nih.gov/30774974/)
- [Adaptation to life after sport: a scoping review](https://pmc.ncbi.nlm.nih.gov/articles/PMC10513329/)
- [Former elite athletes and cardiometabolic health](https://bmjopensem.bmj.com/content/bmjosem/9/4/e001605.full.pdf)

## 重要边界

这是研究和产品交互原型，不是医疗器械、诊断工具或运动处方系统。原型中的心率、RPE、疲劳、疼痛和测试阈值均为演示字段；正式研究前必须由运动医学/康复专业人员确定筛查标准、设备质量要求、急救与人工升级 SOP，并完成伦理审查。
